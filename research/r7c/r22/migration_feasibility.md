# Fractional-bin migration and unknown acquisition timing: evidence and draft experiment

Prepared before any new real-data fit or detection outcome. The R21 manuscript and existing analysis runners are unchanged. This draft is not an outcome protocol and does not authorize running the data. `run_migration.py` requires a separate freeze record containing the final protocol, configuration and runner SHA-256 values.

## Verified processing information

**IPIX.** All 14 local CDFs have `TX_polarization=A`, `PRF=1000`, and the PRF attribute `long_name=Radar pulse repetition frequency per polarization`. This directly supports a 1 ms look interval for each separately loaded like-polarization stream. The provider tutorial says a sweep includes both polarizations when transmission alternates; it is less explicit about whether its generic PRF is total or per-polarization. The actual files resolve that ambiguity; no correction of the current 1 kHz physical conversion is warranted. The range variable labels its entries as near edges and spaces them by approximately 15 m. `Pulse_length=200 ns` supplies a transmitted duration, not a complete receiver impulse response. The 14-bin ADC arrays are already gated samples. Neither the local CDF variables nor the provider loading recipe supplies a complex range PSF or raw fast-time waveform sufficient to recover one. A rectangular 200 ns transmitted pulse does not establish the received fractional-bin response. Primary documentation: https://soma.ece.mcmaster.ca/ipix/dartmouth/cdfhowto.html and https://soma.ece.mcmaster.ca/ipix/dartmouth/datasets.html.

**NetRAD.** The primary publication reports 2.4 GHz, 45 MHz linear up-chirp, 1 kHz PRF, and 130000 pulses in 130 s: https://eprints.gla.ac.uk/118590/1/118590.pdf (Section 2). The downloaded raw MATs contain only `Data_matched` with shape 130000 by 1024 and complex-double storage. The provider's `NR_Range_Selection_June9.m` explicitly calculates the node-3 range axis as native MATLAB bin index multiplied by 6 m. Thus **6 m is verified sample spacing**, while the nominal rectangular-bandwidth first-zero scale `c/(2*45 MHz)=3.331 m` is an ideal response scale. They must not be conflated. The native-bin mapping is retained in the existing processed cache.

The public archive's directory lists two MATLAB scripts and a log spreadsheet as its metadata. All three were downloaded here by HTTP range request and passed archive CRC checks. The log confirms the pulse lengths but supplies no complex PSF or pulse-compression recipe. `NR_PreProcessDataForAmpl_June9.m` begins from `Data_matched`; it does not reproduce pulse compression. `NR_Range_Selection_June9.m` supplies range-bin selection and passive-node phase correction. Neither gives the reference waveform, receive filter, taper, decimation/aliasing treatment, or the resulting fractional-bin complex PSF. Therefore a verified hardware-PSF migration experiment is **not currently supported**. This is an evidence limit, not a reason to manufacture a PSF from the range spacing. The complete public archive directory and metadata hashes are retained in `provider_metadata/`.

The existing NetRAD cache removes each bin's mean and scales each bin to unit power. Adding an equal-amplitude PSF directly to those normalized bins would silently assign different physical target amplitudes to different native bins. The proposed runner instead reads the raw selected bins after freezing, records the fixed mean/power transform, and transforms a common-amplitude target through the same bin gains.

## Minimal useful, feasible study

NetRAD provides long contiguous provider-identified clutter groups, making it preferable to IPIX's separated clutter bins. The draft configuration selects four disjoint three-bin groups by equally spaced **native index alone**, before reading any new samples. It reuses the 14 recordings and the two prior train/calibration/test rotations with 2000-pulse split gaps. The samples have already been used in R15: this is a new question on reused data, not untouched dataset confirmation. All observed pulses are retained so acquisition null false alarms include the recorded anomalies.

Each episode includes a 40-pulse prefix and a 1024-pulse search, about 1.064 s in total. The tested pulse endpoints are identical for every detector. The detector receives a fixed three-bin region, without target crossing time or true Doppler. Each detector calibrates its maximum score over **all three bins and all 1024 pulse endpoints** at acquisition false-alarm probability 0.01. Its held-out null event is any threshold crossing in that exact search window. This explicitly measures the multiple-look acquisition error instead of reusing a per-look 0.01 threshold.

Compare guarded IN-ARCP at guards 0 and 8; raw CA and raw median OS with the **same 16-pulse guarded histories**; an eight-pulse sliding coherent PAMF-H-style AR(1) Doppler-bank maximum at guard 8; and a 16-innovation current-dwell-normalized P-ANMF1-N16 maximum. All whitening coefficients are fitted from the same provider-identified clutter training third, with all observed pulses retained. The PAMF-H comparator's numerator necessarily uses eight pulses. Its 16-sample scale history precedes the dwell, so it uses seven more past samples than the per-look statistic; this support difference is reported. P-ANMF1-N16 uses only the current 16 innovations, so it avoids normalization by contaminated historical target energy and supplies a relevant persistent-target comparator. Every coherent dwell ends at the same tested endpoint as the other methods; no known dwell alignment or oracle Doppler is supplied. The existing AR(4) PAMF-H runner assumes a step target at the first dwell pulse, so its startup steering is not reused for a continuous unknown-timing target. The new comparators use steady-state AR(1) steering and an explicit 64-frequency grid. P-ANMF1-N16 is explicitly a variant of the existing normalized coherent statistic, not a claim to have reproduced the manuscript's AR(4), eight-pulse implementation.

The target is a continuously moving point scatterer, present in the prefix as well as the search. There is **no artificial step onset, clipped support, or ramp**. Its raw matched-filter-domain response is

`target(t, bin) = amplitude * sinc(2 * effective_bandwidth * (bin_range - target_range(t)) / c) * exp(-i * 4*pi*carrier*speed*t/(c*look_rate))`.

The sinc is an **idealized rectangular-spectrum, zero-phase response**, not NetRAD's verified response. Effective bandwidths 22.5 and 45 MHz bracket main-lobe width as a sensitivity choice; they do not identify a receiver setting. Their sampled responses use the documented 6 m bin spacing. Carrier phase/Doppler and migration use the **same signed radial speed**, ±5 and ±15 m/s. Unrelated random Doppler is not added. Native-center crossing time is random in search looks 128 through 895, independent of clutter and amplitude. SCR values are 0, 10 and 20 dB, referred to the theoretical on-center peak power relative to surrounding uninjected measured power at the central native bin. That reference includes any observed anomalies and is not an independently certified clean-clutter level. A single CN(0,1) amplitude is held over the full episode, including the prefix. That coherence/fluctuation assumption and the assumption of a common phase reference across range bins are additional idealizations. The target is not reconstructed from a real trajectory, measured RCS or externally labeled target.

Primary outputs: acquisition null false-alarm count/denominator and ratio to 0.01; probability of any declaration anywhere in the fixed search region; probability of a declaration at a native bin no farther than one sample spacing from the simulated target at declaration time; and time of the first such local declaration relative to central-bin crossing. The broad acquisition event includes chance clutter alarms and must be shown beside the local criterion and null acquisition rate. A secondary conservative event reports whether the **first** acquisition declaration is spatially local, because an early false declaration can matter operationally. First local acquisition before native-center crossing is retained with a negative delay, not suppressed as an inconvenient outcome. All detector settings are compared at their measured null acquisition rates, with recording-cluster uncertainty and per-recording counts; the one-day recording dependence is disclosed.

## Scope and cost

This experiment can test whether a guard retains an advantage when cell emergence follows a continuous response rather than a rectangular onset and whether that survives calibration of the full search. It cannot validate the actual hardware response or real maritime acquisition. The credible outcome might be that guard gains disappear: an eight-look guard spans only 0.04 m at 5 m/s, far smaller than a several-metre response. No required improvement is assumed.

Each native recording is approximately 2.13 GB as complex128 before range selection; the selected 41–101 bins occupy roughly 85–210 MB. SciPy loading may require several GB of temporary memory. Prepare one recording at a time after the freeze, retaining normalized selected bins and original bin gains in hashed per-tag caches. The caches can then be scored by four disjoint recording jobs with `--require-prepared --tags ...`, sharing no raw MAT loads and writing uniquely named per-unit outcomes. Every per-unit manifest records a unique execution job ID. The maximum resident selected-bin data per scorer is about 210 MB, and sixteen-window score batches add approximately 100–200 MB; local-power cumulative arrays add roughly 210–310 MB transiently. Four scorers are therefore conservatively estimated below 4 GiB, apart from OS page cache and unrelated jobs. Four simultaneous full SciPy raw MAT loads are not warranted under a 12 GiB memory allowance. Serial preparation must finish before those parallel jobs start.

Four nonoverlapping groups and complete nonoverlapping 1064-sample episodes produce about 150–160 calibration and test windows per unit by geometry alone, approximately 4300 trials across 28 units. For a header-sized 130000-pulse recording with no trailing-zero drop, the planned split geometry gives 152 windows in A/B and 160 in C, hence 4256 test windows across the 28 rotations. These are conditional planning counts; exact counts are written only after the protocol is frozen and data are loaded. With n=152–160 and alpha 0.01, `ceil((n+1)*0.99)=n`: the split-conformal threshold is the **largest calibration maximum**. The ideal i.i.d. continuous rank tail mass is `1/(n+1)`, approximately 0.0062–0.0065, which is conservative relative to the nominal 0.01. Temporal and cross-bin dependence may invalidate that i.i.d. interpretation; the measured held-out acquisition false-alarm rate is mandatory. Actual sample count, rank and ideal tail mass are saved in each unit manifest. This calibration is finite but noisy, so per-recording uncertainty and pooled/cluster summaries are essential. The design does not claim a 10^-3 or 10^-4 acquisition result.

There are 24 injection conditions (four signed speeds, two ideal bandwidths, three SCRs), sharing the target amplitude and crossing-time draws across competitors and SCR. Dense sliding Doppler-bank calculations dominate cost: each look tests 64 frequencies over eight and sixteen innovations. A 16-window batch caps large intermediate arrays; no GPU or learned model is required. A deterministic fabricated-array timing probe of the complete eight-method score function took 0.453 s for sixteen 1024-look, three-bin windows on the current machine. Scaling that probe gives approximately 55 minutes for score computation across all units, plus raw loading, hashing and preprocessing; it is not a runtime guarantee or a real-data outcome. The runner must be independently checked before the freeze and run. No new real-data fit, threshold, null rate or target outcome has been computed during this assessment.

## Decisions requiring protocol closure

The draft settings and explicit ideal-response scope need to be accepted in a hashed protocol before any outcome. If a **realistic hardware response** is mandatory, this study must remain blocked on provider waveform/filter/decimation metadata or a measured point-target response; the idealized study cannot be relabeled to satisfy that requirement. Real-target validation remains a separate dataset/annotation task.
